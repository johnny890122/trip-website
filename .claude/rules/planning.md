# 排行程的規則（動線、餐廳、票價）

## 動線
- 改任何時間表前，先把當天地點按順序排一遍，確認是**單向掃過**（例如由北往南、由西往東），
  **同一區域不可去了又回**。出國時間很寶貴，每一段多餘的交通都是浪費（「甲地 → 乙地 → 回甲地」這種折返是低級錯誤）
- 使用者說「X 優先」時，只排 X 的**核心場次**；附屬儀式如果會造成折返就不排
- 新增一個點前先算交通成本：順路（在原本就要走的路線上）或值得專程才加，並在卡片上寫明代價與不去的走法
- **每天第一張交通卡要從住宿算起**：不要寫成「08:30 某某車站 → 景點」，先從住宿走到車站，那段步行時間也要算進去。
  抵達日從航班落地算起（入境、領行李、買票的時間沒查到就寫「估算」並留餘裕）；分頭行動時兩條線各自從自己的起點算
- **趕預約或趕班次的交通要寫出「一定要搭的那一班」**，以及錯過時下一班是什麼、會晚多少；下一班查不到就寫「下一班未查到」和備案（別的路線、計程車），列進出發前要查的清單。
  班次本身查不到的公車、船，不要寫得像查過的班次：標題 `.tl-title` 寫「約 HH:MM（班次未查到）」，前後留餘裕。
  `.tl-time` 一律只寫 `HH:MM`（它是 `routes.json` 的 key，`build-places.js` 靠它排序），「約」「估算」寫在標題或內文
- **市區班距短的地鐵、電車不寫死班次**：寫「隨到隨搭、班距約 N 分、車程 N 分、票價」，可以轉車；班次少的（中距離、指定席、地方鐵道、公車、接駁車）才寫那一班
- 步行時間用 OSRM 算，以 80 m／分換算；沒有數字的寫「約 N 分（估算）」。步行要用 **foot** 的網址（預設的 `router.project-osrm.org` 只有開車）：
  `https://routing.openstreetmap.de/routed-foot/route/v1/foot/<經度>,<緯度>;<經度>,<緯度>?overview=false` → 回傳的 `routes[0].distance`（公尺）÷ 80，四捨五入到分（9.2 → 9、15.4 → 15、15.7 → 16）
  - 走到車站時，終點是**實際要進的那個改札或出口**（例：池袋 JR 東口改札），不是車站的任意一個點；起訖座標寫進筆記。住宿 → 車站的分鐘數查一次就寫進 `trips/<id>/CLAUDE.md`「這趟的規則」，每天的第一張卡都用同一個數字
- 看夕陽、爬山前查當地日落時刻，排在天黑前結束

## 餐廳
- 每一餐是「彈性」項目：方案 A 是首選，B～D 是替代；**同一家店不出現在不同天**；每一家都要確認**那天那個時段有開**（公休日），配合當天的區域與前後行程
- 優先選評價高、有人氣的店（當地評分網站的評分與評論數、得獎紀錄，近五年的部落客、論壇與社群評價）
- 人數多時要檢查：席數夠不夠、要不要分桌／分批、有沒有包廂、能不能預約、限時多久，寫在卡片的 `⚠️ 注意`
- 使用者指定的店、使用者給的清單**優先於 AI 推薦**；指定了就不再加替代店。
  挑店的限制（例：有小孩不排居酒屋、同一家店不出現在不同天）是給 **AI 挑的店**用的：使用者清單上的店照排，只查營業、席數、能不能帶小孩，有疑慮寫在 `⚠️ 注意`，不要自己拿掉
- 當地語言的店名沒查證過就不寫，只寫查得到的寫法；地圖連結 `?q=` 和 `trips/<id>/coords.json` 的 key 用完全相同的字串
- 小卡的格式（`.plan-ref`：店名、特色、⭐ 評分＋查詢年月、🏅、🕐、🎫、📍、⚠️、地圖與查證來源）見 `.claude/rules/itinerary-page.md`（方案輪播）

## 票價與預算
- 行程表上已查證的門票與另外購買的車票（指定席、高速巴士、套票），同步寫進 `docs/<id>/budget/index.html` 的 `fixed`；**改票價時兩邊一起改**；彈性方案不算；主行程卡裡「現場決定要不要買」的（例：江の島エスカー）也不算，卡片寫「預算不計」；IC 卡扣款的車資不算（儲值金額已經算過一次）
- 敬老、兒童票價不同時，預算以大人價計，卡片寫出差異
