# 查證（調度）

要查的：$ARGUMENTS

目前的旅行： !`ls trips | grep -v '^_' || true`（沒寫是哪一趟就用 id 最大的）

1. 先 grep `trips/<id>/reference/`：已經查過的直接引用，不派人
2. 剩下的拆成**互不相干**的問題（一家店、一條路線、一個景點各一個）
3. 每個問題派一個 `trip-researcher` agent，**同一則訊息一起派**（並行）；最多 5 個，多的分批。每個任務要自己寫清楚，因為 agent 看不到這段對話：
   - 哪一趟（id）、哪一天（日期＋星期）、哪個時段、幾個人
   - 要查的問題與要回報的欄位
   - 店名、地名**照使用者原文抄**（有地址或地圖連結就一起附上），不要自己補分店名：補錯的分店名會讓查證員去查一家不存在的店
   - 筆記檔名：`trips/<id>/reference/<MMDD>_<主題>_查證筆記.md`，**每個 agent 不同**（同時寫同一個檔會互相蓋掉）
4. 有 agent 中途失敗（API 錯誤、斷線）：用**同一份任務、同一個筆記檔名**重派；它會先讀筆記，從沒查完的題目接著查
5. 收回來後整合成一張表（事實｜值｜來源｜等級），標出互相矛盾的與「未查到」的
6. 結論要寫進頁面時用 `itinerary-edit` skill；這個 skill 本身不改 `docs/`
