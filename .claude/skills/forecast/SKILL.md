# 天氣預報

旅行：$ARGUMENTS（沒寫就用 `trips/` 裡 id 最大的那一趟）

1. 讀 `trips/<id>/CLAUDE.md` 的「天氣預報」：要抓的網址、紀錄表在哪一份筆記、欄位是哪幾天哪些地點
2. 每個網址**用 Bash 的 curl 抓原始 HTML 再 grep**，不要用 WebFetch：WebFetch 會先經過摘要，降水機率會被改掉（2026-11 E2E：頁面 10%，摘要寫成 40%）。tenki.jp 的抓法見 `reference/regions/japan.md`。記頁面上的**發表時間**（不是現在時間），每一天：天氣、降水機率、降水量（有分時段就記分時段）、最高／最低
3. 在紀錄表最下面追加**一節**（標題是發表時間），每個地點一列、每天一格，格式照前面的節；不改舊的節。第一次沒有可以比的，回報寫「第一筆」
4. 回報：
   - 新的一節，以及和上一節相比變了什麼
   - 哪幾天的行程受影響（戶外景點遇高降雨機率、山上低溫、看富士山或夕陽的時段是陰天）與建議
   - **不改頁面**；使用者要改時用 `itinerary-edit` skill
5. 那一趟沒有列網址時，從「每天的主題」挑出**還沒到的日子**會去的市區町村（一個地點一個網址），日本用 tenki.jp 10 日間（依市區町村代碼）或氣象廳；
   把網址與紀錄表的位置寫回 `trips/<id>/CLAUDE.md` 的「天氣預報」，紀錄表建在 `trips/<id>/reference/forecast_查證筆記.md`。地點看不出來才問使用者
