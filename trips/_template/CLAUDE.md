# 〔YYYY-MM〕〔旅行名稱〕

這一趟的事實與只適用這趟的規則。通用的資料整理規則在根目錄 `CLAUDE.md`，網站與腳本在 `.claude/rules/`（碰到相關檔案時自動載入），地區的查證方法在 repo 根目錄的 `reference/regions/`。
寫好的例子：`trips/2026-11/CLAUDE.md`。

> 查證筆記都在 `trips/〔YYYY-MM〕/reference/`；每個數字都要能在筆記裡找到來源，筆記沒有的不要寫。〔查證日期 YYYY-MM-DD〕
> 還沒有日期、航班時，只填「概述」和「候選」，不要排每天的時間表。

## 概述
- **日期**：〔YYYY 年 M 月 D 日（○）～D 日（○），N 天 N 夜〕
- **成員**：〔幾位大人、幾位小孩（年齡）；有沒有長輩、體力差異〕〔組別名稱（使用者命名）〕
- **主題**：〔地區與重點〕
- **地區**：〔國家、城市〕〔有 repo 根目錄 `reference/regions/<地區>.md` 的寫上檔名，例：日本 → `reference/regions/japan.md`〕
- **正式行程**：`docs/〔YYYY-MM〕/final/index.html`

## 這趟的規則（使用者明確要求，只適用這趟）
- 〔例：哪裡不排計程車、哪些交通要寫死班次、家庭的特殊需求、簡化版的寫法〕
- 〔每天第一張交通卡從哪間住宿算起：住宿 → 最近車站步行 N 分（OSRM）〕
- 〔有推車、長輩、大行李時，每段轉乘與步行多留幾分鐘的餘裕（itinerary-reviewer 照這個數字審）〕

## 候選（還沒排進行程的）
- 〔景點、美食、活動；每一個附查證筆記的檔名〕
